# Delivery Phasing

This project benefits from concrete slices instead of vague website ambition.

## 1/3 — Build safely

Goal: publish the smallest truthful website that is already useful.

Scope:

- homepage
- downloads page
- proof / validation page or section
- links to canonical repo docs
- GitHub Releases-backed asset links
- explicit verified-primary vs preview labeling

Definition of done:

- a new visitor can understand the product, locate the beta, and avoid the wrong expectations

## 2/3 — Build + iterate + first shareable version

Goal: make the site feel more complete and more persuasive without widening claims.

Scope additions:

- stronger visual system
- screenshots or UI stills if available
- benchmark summaries or charts
- better contribution / beta feedback funnel
- tighter docs hub or FAQ structure

Definition of done:

- the site is good enough to share broadly without the repo doing all the explanatory work

## Full — Build + ship professionally

Goal: create a launch-grade site that can support ongoing releases with lower friction.

Possible additions:

- automated release metadata updates
- richer changelog / release archive browsing
- custom domain
- stronger visual storytelling assets
- improved comparison / proof surfaces once evidence broadens

Definition of done:

- the website feels like a maintained public product surface rather than a strong beta landing page
