# Website Specification Pack

Specification pack for the first public website and download surface for AMD Video Enhancer.

- **Inference level:** low
- **Created against:** published beta prerelease `v0.1.0-beta.1`
- **Primary goal:** design a public website that helps visitors understand the project, validate the claims, and download the correct beta assets without being misled about support breadth

## Pack contents

- `project-brief.md` — product and communication goal for the site
- `requirements.md` — functional and non-functional requirements
- `constraints-and-assumptions.md` — truth-surface constraints and explicit assumptions
- `user-experience-spec.md` — audience, journeys, page structure, and interaction goals
- `technical-specification.md` — recommended site architecture and deployment model
- `content-proof-matrix.md` — allowed public claims mapped to proof sources
- `delivery-phasing.md` — staged rollout plan for the site
- `open-questions.md` — unresolved decisions worth answering before implementation
- `inference-ledger.md` — explicit vs inferred decisions for this pack

## Design intent

This website should feel:

- sharp
- technical
- honest
- AMD-first
- beta-aware
- download-focused

It should **not** feel like:

- generic AI startup marketing
- a fake GA launch
- a compatibility promise broader than the repo can prove
- a beautiful shell that hides the support and limitation story

## Primary public jobs

1. Explain what the project is and why it matters.
2. Let visitors download the beta assets safely.
3. Make support boundaries and host requirements obvious before download.
4. Give skeptical visitors enough proof to trust the site.
5. Send deeper readers into the repo docs instead of trying to cram every detail into the homepage.
