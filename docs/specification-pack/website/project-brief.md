# Project Brief

## Working title

AMD Video Enhancer website and beta download surface

## Problem

The repository now has a live beta prerelease, but the public front door is still mostly the GitHub repo itself. That is workable for technical contributors, but weak for:

- AMD users who want to know quickly whether the project is real and downloadable
- skeptical visitors who need proof before trusting the claims
- testers who need to understand what is verified versus preview before choosing an asset
- future documentation and launch work that needs a clean website-shaped truth surface

## Goal

Create a public website that turns the current release truth into a clear, trustworthy, download-ready experience.

The website must help a visitor answer four questions fast:

1. What is this?
2. Why should I care?
3. What can I actually download today?
4. What is verified, preview, or out of scope?

## Target audiences

### Primary

- AMD GPU users on Linux looking for a real beta to try
- technically skeptical developers who want proof before trust
- testers who need an explicit support and validation surface

### Secondary

- contributors deciding whether the project is serious enough to invest in
- readers interested in the broader AMD-first / MiGraphX / vibe-coded story

## Success criteria

The first website version is successful if it:

- gives the beta release a clean public home beyond the raw repo landing page
- drives visitors to the correct GitHub release assets
- prevents misunderstanding about support breadth
- highlights the verified primary environment clearly
- makes the project's strategic argument legible without sounding inflated

## Non-goals for the first version

- full marketing-site breadth with many filler pages
- broad benchmark theater or visual-comparison overclaiming
- pretending the project is already general-availability software
- building a complex CMS or backend-driven website
